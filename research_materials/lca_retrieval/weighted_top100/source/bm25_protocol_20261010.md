# BM25 comparator: exploratory reused-cohort study

Approved by the author on 2026-10-10, before computing BM25 scores.

## Question and scope

Does the previously fixed dense/structural combination outperform a conventional
lexical retriever and a development-calibrated dense/lexical combination?
This is a missing baseline comparison, not a new method or a confirmatory test.
Both cohorts have already been analysed. No unused problems, new encoding,
training, GPU resources, Java test data or CPRet data are accessed.

## Fixed comparator

Use the existing Python `lexical_token_stream`: token type and original spelling,
including identifiers, literals and operators, excluding comments and formatting.
No stemming, subtoken splitting, stopword list or identifier anonymisation.
The complete program is used, as in the earlier lexical baseline.

For gallery size N, document frequency df(t), raw document count f(t,d),
raw query count f(t,q), document length L(d) and gallery mean length avgL:

    idf(t) = log(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
    B(q,d) = sum_t f(t,q) * idf(t) * (k1+1)*f(t,d)
             / (f(t,d) + k1*(1-b+b*L(d)/avgL))

Fix k1=1.2 and b=0.75. Count every query token occurrence (no query saturation).
Fit vocabulary, document frequencies and mean length on the gallery only;
query-only terms contribute zero. Use exact lengths and float64 arithmetic.
This is the positive-IDF BM25 formula with Lucene defaults, NOT a bitwise
reproduction of Lucene (which has its own analysis and compressed norms).
The factor k1+1 does not affect ranks or the subsequent min-max scaling.

For each query, independently min-max scale all 5200 gallery scores for both
channels: M(s)=(s-min(s))/(max(s)-min(s)); a constant channel becomes zero.
The hybrid is (1-alpha)*M(D)+alpha*M(B). Endpoints alpha=0/1 use the original
channel rankings, preserving ties exactly. No top-K truncation in this study.

Choose alpha from the EXISTING 24-value grid in
`conditional_structure_pilot_20261010.py`, maximising problem-macro MAP@8 on
the SAME 325 calibration problems in its design receipt. Exact objective ties
choose the smallest alpha. Record every grid value. Freeze the selected alpha
before evaluating the other 325 old problems and the later 650-problem cohort.
Do not tune k1, b, tokenisation, normalisation or a new grid after seeing results.

## Evaluation and interpretation

Old internal validation: D, BM25, calibrated D+BM25; 2600 queries against the
unchanged 5200-item gallery (including calibration-problem gallery entries).
Later cohort: 5200 queries / 5200 gallery items / 650 problems; compare those
three methods with the existing root-TF-IDF (.20), root-TF without IDF (.25),
and node-count (.50) hybrids. Structural weights, scores and normalisation stay
unchanged. The structural and BM25 hybrid alpha values are not on a common
scale: the former mixes cosine scores, the latter min-max scores.

Report MAP@8 (eight relevant items per query, denominator eight), full-ranking
MRR, and Success@10 (any relevant result). Resolve score ties by UTF-8 source ID.
Report all point differences and improved/tied/worsened problem counts; no new
p-values, confidence intervals, equivalence claims or subgroup searches.
The comparison cannot establish universal superiority over lexical retrieval:
one fixed code tokenizer and one BM25 configuration are examined.

Sparse term counts, vocabulary, calibration values and per-query results are
retained. Full new score matrices are not needed. Check the formula against a
direct scalar calculation and check rankings/metrics with an independent sort.
Record pipeline wall time for reproducibility, not as a serving-latency claim.
Run locally on one CPU thread at reduced priority, without modifying frozen
experiments, existing artifacts or the manuscript.

## Sources

- [Apache Lucene 10.3.1 BM25Similarity](https://lucene.apache.org/core/10_3_1/core/org/apache/lucene/search/similarities/BM25Similarity.html): positive IDF and default parameters.
- [Lucene implementation](https://github.com/apache/lucene/blob/releases/lucene/10.3.1/lucene/core/src/java/org/apache/lucene/search/similarities/BM25Similarity.java): implementation differences matter.
- [rank_bm25 implementation](https://github.com/dorianbrown/rank_bm25/blob/master/rank_bm25.py): summation over query occurrences; its default k1 and IDF differ from the fixed formula above.
- [Bruch, Gai and Ingber, An Analysis of Fusion Functions for Hybrid Retrieval (2023)](https://arxiv.org/abs/2210.11934): score-normalised convex fusion and development calibration; not evidence about this code-retrieval dataset.
